# Исправление: в APK были файлы Whisper tiny вместо base

Эта версия помечена `0.2.1` (`versionCode = 4`). Workflow и артефакт специально переименованы, чтобы старую сборку tiny было трудно перепутать с новой.

## Важно при обновлении GitHub

1. Загрузите содержимое каталога `VoiceNotesAndroid-main` в корень репозитория и **перезапишите** `.github/workflows/android.yml` этой версией. Не просто добавляйте рядом файлы старого проекта.
2. В GitHub откройте **Actions** и выберите workflow с точным названием:
   `VoiceNotes Android — Whisper BASE v0.2.1 (strict model check)`.
3. Запустите **Run workflow** и дождитесь зелёного статуса.
4. В этом же запуске скачайте только артефакт с точным именем:
   `VoiceNotes-APK-WHISPER-BASE-v0.2.1`.
5. Убедитесь, что это новый APK версии `0.2.1`, установите и попробуйте диктовку.

Не используйте артефакт `VoiceNotes-debug-apk-offline-whisper`: это имя старой сборки и по нему нельзя удостовериться, что была использована модель base.

## Что проверяет новый workflow

- Удаляет целиком `app/src/main/assets`, прежде чем раскладывать модель — старые tiny-файлы не могут остаться от предыдущего запуска.
- Загружает официальную multilingual Whisper base модель sherpa-onnx и проверяет наличие encoder, decoder и tokens.
- Добавляет файл-маркер `model-version.txt` со значением `whisper-base-int8-v0.2.1`.
- После сборки проверяет **содержимое именно APK**: encoder base, decoder base, tokens и маркер должны быть внутри; любые файлы модели tiny заставляют workflow завершиться ошибкой.

Если workflow красный, APK публиковаться не будет — откройте его logs, это позволит увидеть причину. Полную Android-сборку в подготовительной среде я не запускал: нет Android SDK/Gradle и сетевого доступа к скачиванию зависимостей и модели. Статические проверки можно выполнить локально, а фактическая проверка APK производится самим workflow в GitHub Actions.
